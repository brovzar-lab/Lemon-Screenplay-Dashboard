# Q8.1 Private Reader Chat

## Producer experience

Each specialist reader in the Reader Room has a **Talk privately** action. A producer can ask any free-form question about the screenplay, return to the same saved conversation later, and see page citations beside the reader's answer.

The reader can clarify the sealed report or publish a clearly labeled reconsidered private position. A reconsideration never changes the original report, score, shared synthesis, or producer calibration evidence.

## Grounding and provenance

Every live conversation is bound to all of the following:

- The signed-in Lemon Studios user.
- One project and one immutable analysis version.
- One specialist reader and that reader's sealed independent report.
- The exact screenplay PDF object and Storage generation recorded by that version.
- One version-controlled Markdown reader charter and its SHA-256 hash.
- The centrally registered conversation model and the date that model choice was verified.

The screenplay PDF is treated as evidence, not instructions. The secure service loads all source material server-side. The browser cannot choose a different report, PDF, charter, or model.

## Saved conversations

Live conversations are stored by the secure Cloud Function in `reader_conversations`. A stable private thread is derived from user, project, version, and reader. Every message records its order, timestamp, citations, response identifier, model identifier, and usage accounting when present.

Client-side Firestore access is not added. Conversation reads and writes remain behind verified `@lemonfilms.com` authentication and the existing server-side LLM budget ledger.

## Model policy

Private Reader Chat uses `claude-fable-5` at its recommended high-effort default, verified against Anthropic's current model catalog on 2026-08-02. Fable's adaptive thinking runs automatically, and the request receives the full approved output allowance so difficult questions still have room for a structured answer. The choice lives in `functions/src/modelRegistry.ts` so it can be reviewed and upgraded deliberately. The V9 scoring pipeline keeps its existing pinned models because changing them would change scoring behavior.

## Safe local review

Local development defaults to `local_review` mode. The interface saves conversations in the browser and assembles a clearly labeled response from the sealed report so the complete user experience can be reviewed without a network request, model call, or charge.

Two independent gates are required for live use:

1. `READER_CHAT_ENABLED=true` in the Functions environment.
2. `VITE_READER_CHAT_LIVE=true` in the hosting build environment.

Until both gates are approved and deployed, production stays inactive and local review stays no-cost.

## Activation checklist

1. Review the Reader Room and all five private conversations locally.
2. Approve a coordinated Functions and hosting deployment.
3. Enable both gates above.
4. Run one paid conversation against a known screenplay and verify its citations.
5. Confirm the saved conversation survives a reload and the sealed score remains unchanged.
