# Q8.1 Private Reader Chat

## Producer experience

Each specialist reader in the Reader Room is a direct entrance to that reader's private conversation. The conversation replaces the report panel so it feels like a focused chat, while **View report** returns to the sealed analysis in one click. A producer can ask any free-form question about the screenplay, return to the same saved conversation later, and see page citations beside the reader's answer.

The producer's message appears immediately. The reader then shows a visible thinking state and reveals the answer progressively in short conversational paragraphs. **Enter** sends, **Shift+Enter** adds a line, and **Show full response** skips the reveal. Reduced-motion preferences show the complete response immediately.

The reader can clarify the sealed report or publish a clearly labeled reconsidered private position. A reconsideration never changes the original report, score, shared synthesis, or producer calibration evidence.

## Grounding and provenance

Every live conversation is bound to all of the following:

- The signed-in Lemon Studios user.
- One project and one immutable analysis version.
- One specialist reader and that reader's sealed independent report.
- The exact screenplay PDF object and Storage generation recorded by that version.
- One version-controlled Markdown reader charter and its SHA-256 hash.
- The centrally registered routing policy, exact model, effort, routing reason, attempts, usage, cost, and the date the model registry was verified.

The screenplay PDF is treated as evidence, not instructions. The secure service loads all source material server-side. The browser can request only the three approved routing modes. It cannot choose an arbitrary model, report, PDF, or charter. Opus 5 and Fable 5 are service-only in the general LLM proxy, so a signed-in browser cannot bypass the Reader Chat gate or its sealed evidence policy.

## Saved conversations

Live conversations are stored by the secure Cloud Function in `reader_conversations`. A stable private thread is derived from user, project, version, and reader. Every reader response records its order, timestamp, citations, response identifier, exact model, high-effort setting, requested mode, routing reason, every attempted model, and usage and cost accounting when present. If a route ends without an answer, the same complete attempt chain is written to the thread's append-only `routing_audits` collection before the error returns; the interface discloses the latest stopped attempt without presenting it as a reader answer.

Client-side Firestore access is not added. Conversation reads and writes remain behind verified `@lemonfilms.com` authentication and the existing server-side LLM budget ledger.

## Model policy

Private Reader Chat uses the first-party Lemon Model Router, verified against Anthropic's current model catalog on 2026-08-02:

- **Auto**, the default, starts with `claude-opus-5` at explicit high effort.
- **Opus 5** forces `claude-opus-5` at high effort without escalation.
- **Fable 5** forces `claude-fable-5` at high effort for the deepest direct review.
- **Fable deep review** repeats a prior producer question as a visible second opinion and preserves both responses.

Auto may escalate to Fable only for an objective safe failure: an Opus refusal or an invalid grounded tool response. It does not retry budget failures, invalid requests, unknown failures, network failures, unreadable proxy responses, or uncertain post-call accounting because those cases could create an unsafe or duplicate charge.

The policy lives in `functions/src/readerChatRouting.ts`; the approved models live in `functions/src/modelRegistry.ts`. The V9 scoring pipeline keeps its existing pinned models because changing them would change scoring behavior.

## Safe local review

Local development defaults to `local_review` mode. The interface saves conversations in the browser and assembles a clearly labeled response from the sealed report so Auto, Opus, Fable, deep-review, routing provenance, citations, and saved history can all be reviewed without a network request, model call, or charge.

Two independent gates are required for live use:

1. `READER_CHAT_ENABLED=true` in the Functions environment.
2. `VITE_READER_CHAT_LIVE=true` in the hosting build environment.

Until both gates are approved and deployed, production stays inactive and local review stays no-cost.

## Activation checklist

1. Review the Reader Room and all five private conversations locally.
2. Approve a coordinated Functions and hosting deployment.
3. Enable both gates above.
4. Run one paid conversation against a known screenplay and verify its citations.
5. Confirm the saved conversation survives a reload and the sealed score remains unchanged.
